# Stage 07 — Solutions Index and Textile/Dyehouse Vertical

## Objective

Make Dima's specialization concrete without claiming customer deployments or unsupported domain integrations.

## Solutions index

Create clear paths for:

- operations;
- production/OEE;
- finance;
- sales/customer;
- inventory;
- executive reporting.

Every path should lead with a question, then show the mechanism and the role-level outcome. Avoid generic “AI for every team” cards.

## Textile/dyehouse page

Use this narrative:

1. sector-specific hero;
2. dyehouse data questions;
3. batch/recipe/machine relationship visual;
4. OEE and waste proof;
5. quality/color deviation;
6. water, energy, and chemical cost;
7. order deadline and shipment risk;
8. guard/provenance trust surface;
9. qualified demo CTA;
10. FAQ and related links.

Sanitized question examples:

- machine × shift OEE;
- highest waste stage;
- recipe-based chemical cost;
- color deviation by batch;
- water/energy per kilogram;
- orders at deadline risk.

## Tasks

1. Keep domain examples fictional and clearly illustrative.
2. Reuse the same Dima proof system but change the question and data vocabulary.
3. Use domain-specific labels only when a real user can understand them; explain abbreviations such as OEE.
4. Separate “built for this workflow” from “integrates with every textile system.”
5. Link to Product, How It Works, Security, and Contact.

## Acceptance criteria

- Solutions cards are scannable and question-led.
- Textile page feels specialized without making a customer/certification claim.
- Data relationships are understandable without exposing a real schema.
- The page works in Turkish and English without clipped domain terms.
- The primary CTA is qualified and honest.

## Verification

Check all route links, metadata, mobile stacking, keyboard order, text alternatives for diagrams, and claim status.
