### Before D10-S

The post-acceptance Manager schema was mostly static. It removed some root-only actions when

```text

```

The provider schema and runtime validation are both derived from the same resolved profile.

Key outcomes:

1. Current fresh VERIFIED Evidence is implicit cognition context.
   `inspect_evidence` is not advertised for that Evidence.

3. Post-acceptance `USER_SOURCE resolve_semantics` is not a legal cognition path.

4. `AGENT_DERIVED resolve_semantics` remains possible only under a typed eligible parent.

5. A feasible ROOT_CAUSE parent does not advertise semantic rediscovery merely because a new
   analytical result arrived.

6. A server-owned derived ResearchTask child does not become semantic authority merely because it
   produced VERIFIED Evidence.

7. A non-root accepted parent with an OPEN `ADAPT_ON_EVIDENCE` directive may still expose
   evidence-grounded semantic discovery. D10-S therefore does not globally hide
   `resolve_semantics`.

8. Tight Research headroom prunes structurally dead-end epistemic actions but never increases the
   configured budget.
